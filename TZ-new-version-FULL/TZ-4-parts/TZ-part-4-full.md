# 1. Общая концепция Frontend

Frontend является отдельным клиентским приложением, работающим с Backend через REST API.

Основная задача интерфейса — предоставить максимально понятную и прозрачную информацию как жильцам, так и администраторам.

Главный принцип интерфейса:

> **Пользователь не должен искать информацию — система должна сразу отвечать на его вопросы.**

---

# 2. Основные требования к интерфейсу

Интерфейс должен быть:

* современным;
* минималистичным;
* быстрым;
* адаптивным;
* удобным для работы с телефона;
* одинаково понятным людям любого возраста.

---

## Основные принципы UX

Каждый экран должен отвечать максимум на 2–3 вопроса.

Нельзя перегружать страницы большим количеством информации.

Каждая карточка должна содержать только самое важное.

---

# 3. Поддерживаемые устройства

Frontend должен корректно работать на:

* компьютерах;
* ноутбуках;
* планшетах;
* мобильных телефонах.

Минимальная ширина:

```text
320 px
```

# 24. UX-принципы

Каждый экран должен отвечать на вопрос пользователя за несколько секунд.

### Жилец должен сразу понимать:

* сколько он должен;
* сколько уже оплатил;
* есть ли переплата;
* за какие месяцы произведена оплата;
* где скачать чек.

### Администратор должен сразу понимать:

* сколько денег поступило;
* сколько начислено;
* сколько долгов;
* сколько денег осталось;
* какие расходы произведены;
* кто из жильцов является должником.

---

# 25. Работа с ошибками

Все ошибки должны отображаться понятным языком.

Например:

Не:

```text
500 Internal Server Error
```

А:

```text
Не удалось сохранить платёж.
Попробуйте ещё раз или обратитесь к администратору.
```

---

Если операция выполняется долго:

Показывать:

```text
Загрузка...
```

или индикатор выполнения.

---

# 26. Адаптивность

Все страницы должны корректно работать:

* на телефоне одной рукой;
* на планшете;
* на широком мониторе.

На мобильных устройствах таблицы должны автоматически преобразовываться в карточки или поддерживать горизонтальную прокрутку для сохранения читаемости.

---

# 27. Требования к безопасности интерфейса

Frontend не должен:

* хранить пароли;
* хранить финансовые расчёты;
* выполнять бизнес-логику;
* определять права доступа самостоятельно.

Все проверки прав выполняются Backend.

Frontend только отображает доступные пользователю функции согласно полученной роли.

# 28. Ключевой UX-принцип проекта

Это главный принцип всей системы и одна из её основных ценностей.

## Для жильца

После входа в систему пользователь должен без дополнительных вычислений получить ответы на вопросы:

* Сколько я должен?
* Сколько я уже заплатил?
* За какие месяцы оплачено?
* Есть ли переплата?
* Когда была последняя оплата?
* Где находятся мои чеки?

Эта информация должна отображаться на главной странице личного кабинета.

---

## Для администратора

После открытия Dashboard система должна сразу отвечать на вопросы:

* Сколько квартир обслуживается?
* Сколько начислено за текущий месяц?
* Сколько денег фактически поступило?
* Какова общая задолженность?
* Сколько денежных средств сейчас находится в кассе?
* Какие расходы уже произведены?
* Какой текущий финансовый результат?

Администратор не должен собирать эти данные вручную из разных разделов — они должны быть доступны на главном экране.

---

# 29. Критерии готовности Frontend

Frontend считается завершённым, если:

### Жилец может:

* авторизоваться;
* увидеть состояние своего лицевого счёта;
* просмотреть начисления и оплаты;
* увидеть распределение каждого платежа по месяцам;
* скачать все чеки;
* проверить текущий долг или переплату.

### Администратор может:

* управлять всеми сущностями системы;
* принимать и контролировать платежи;
* отслеживать движение денежных средств;
* управлять сотрудниками и расходами;
* получать аналитические отчёты;
* контролировать финансовое состояние дома в режиме реального времени.
