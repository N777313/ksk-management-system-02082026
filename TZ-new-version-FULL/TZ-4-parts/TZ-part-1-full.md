# 1. Общая информация о проекте

## Название системы

**KSK Management System**

---

## Назначение системы

KSK Management System — это информационная система для управления многоквартирным домом, предназначенная для:

* учёта квартир и жильцов;
* автоматического начисления коммунальных платежей;
* контроля оплаты владельцами квартир;
* прозрачного отображения финансового состояния каждой квартиры;
* управления денежными поступлениями;
* управления расходами дома;
* контроля заработной платы сотрудников;
* формирования финансовых отчётов.

---

# 2. Главная цель системы

Главная цель:

Создать систему полной финансовой прозрачности между жильцами и управляющей организацией (КСК).

Система должна исключить:

* ручной учёт в Excel;
* записи в бумажных журналах;
* ошибки при подсчёте долгов;
* путаницу при оплате заранее;
* потерю информации о расходах.

---

# 3. Основной принцип работы системы

Система должна разделять четыре независимых понятия:

---

## 3.1 Начисления (Charges)

Это:

**Сколько квартира должна оплатить.**

Пример:

```
Квартира №25

Август 2026

Начислено:

5400 ₸
```

---

## 3.2 Платежи (Payments)

Это:

**Сколько денег реально поступило от владельца квартиры.**

Пример:

```
Квартира №25

05.08.2026

Получено:

64800 ₸
```

---

## 3.3 Распределение платежа (Payment Allocation)

Это:

**За какие месяцы была произведена оплата.**

Пример:

```
Оплата:

64800 ₸


Август 2026     5400 ✓

Сентябрь 2026   5400 ✓

Октябрь 2026    5400 ✓

...

Июль 2027       5400 ✓
```

---

## 3.4 Расходы (Expenses)

Это:

**Куда были потрачены деньги дома.**

Пример:

```
Зарплата уборщика:

80000 ₸
```

---

Главная формула системы:

```
Начисления

≠

Платежи

≠

Расходы
```

Они должны учитываться отдельно.

---

# 4. Исходные данные дома

Система должна поддерживать любой дом, но первоначальный сценарий:

## Дом:

```
Количество этажей:

4


Количество подъездов:

6


Квартир в подъезде:

8
```

---

Общее количество квартир:

```
6 × 8 = 48 квартир
```

---

# 5. Коммунальный тариф

Каждая квартира имеет ежемесячный обязательный платеж.

Первоначальный тариф:

```
5400 ₸ / месяц
```

---

Назначение платежа:

* уборка подъезда;
* мойка полов;
* уборка территории возле подъезда;
* уборка мусора возле подъезда.

---

Тариф должен быть изменяемым.

Например:

2026 год:

```
5400 ₸
```

2027 год:

```
6000 ₸
```

Старые начисления не должны изменяться.

---

# 6. Основные пользователи системы

Система имеет три основные категории пользователей:

```
1. Владелец квартиры

2. Администратор КСК

3. Работник дома
```

---

# 7. Роль №1 — Владелец квартиры (Resident)

## Главная задача роли

Получить полную информацию о своей квартире и своих платежах.

---

## Владелец квартиры имеет доступ:

### Информация о квартире:

```
Дом

Подъезд

Этаж

Номер квартиры

Площадь (если используется)

Владелец
```

---

### Финансовое состояние:

Пользователь должен видеть:

```
Общая сумма начислений

Общая сумма оплат

Текущий долг

Переплата

Дата последней оплаты
```

---

Пример:

```
Квартира №25


Начислено:

129600 ₸


Оплачено:

108000 ₸


Долг:

21600 ₸
```

# 9. История начислений владельца

Жилец должен видеть каждый месяц.

Пример:

| Месяц   | Начислено | Оплачено | Статус   |
| ------- | --------- | -------- | -------- |
| Январь  | 5400      | 5400     | Оплачено |
| Февраль | 5400      | 5400     | Оплачено |
| Март    | 5400      | 3000     | Частично |
| Апрель  | 5400      | 0        | Долг     |

---

Статусы:

```
Оплачено

Частично оплачено

Не оплачено

Оплачено вперёд
```

---

# 10. История платежей владельца

Пользователь должен видеть:

```
Дата оплаты

Сумма

Способ оплаты

Чек

За какие месяцы закрыто
```

---

Пример:

```
05.08.2026


Оплачено:

64800 ₸


Закрытые периоды:


Август 2026

-

Июль 2027
```

---

# 11. Принцип работы с переплатой

Если владелец заплатил заранее:

Например:

```
64800 ₸
```

Система должна автоматически определить:

```
64800 / 5400 = 12 месяцев
```

---

Результат:

```
Оплачено:

Август 2026

Сентябрь 2026

Октябрь 2026

...

Июль 2027
```

---

# 12. Принцип работы с долгом

# 15. Главные вопросы администратора

Система обязана отвечать:

---

## Вопрос 1

### Сколько денег должны собрать?

Ответ:

```
Количество квартир × тариф
```

---

Пример:

```
48 × 5400

=259200 ₸
```

---

## Вопрос 2

### Сколько денег реально получено?

Ответ:

```
Сумма всех Payments
```

---

## Вопрос 3

### Кто должен?

Ответ:

Список:

```
Квартира

Владелец

Сумма долга

Количество месяцев долга
```

---

## Вопрос 4

### Сколько денег сейчас есть?

Ответ:

```
Все поступления

-

Все расходы
```

---

## Вопрос 5

### Куда ушли деньги?

Ответ:

```
Категория расхода

Дата

Сумма

Документ
```

# 19. Основные бизнес-сценарии системы

---

# Сценарий №1

## Ежемесячное начисление

Дата:

```
1 число месяца
```

Система:

```
Берёт все квартиры

↓

Создаёт начисление

↓

Добавляет долг
```

---

# Сценарий №2

## Жилец оплачивает каждый месяц

Платёж:

```
5400 ₸
```

Система:

```
Создаёт Payment

↓

Закрывает Charge

↓

Создаёт чек

↓

Обновляет баланс
```

---

# Сценарий №3

## Жилец платит за год

Платёж:

```
64800 ₸
```

Система:

```
Создаёт Payment

↓

Распределяет 12 месяцев

↓

Создаёт переплату
```

---

# Сценарий №4

## Жилец оплачивает долг частично

Система:

```
Сначала закрывает старый долг

Потом будущие месяцы
```

---

# Сценарий №5

## Выплата зарплаты

Администратор:

```
Создаёт выплату сотруднику
```

Система:

```
Создаёт расход

↓

Создаёт движение денег

↓

Уменьшает баланс
```
